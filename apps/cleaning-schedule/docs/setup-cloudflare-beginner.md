# Cloudflare 接続手順（はじめて触る人向け・Windows・ブラウザだけで完結）

このページの通りに進めれば、システムがインターネット上で動き出します。
**ターミナル（黒い画面）も Node.js のインストールも不要**です。すべてブラウザで完結します。

所要時間: 40〜60分。途中で分からなくなったら、その時点で聞いてください。

---

## この作業で何が起きるのか（先に全体像）

```
  ① Cloudflareのアカウントを作る
        ↓
  ② データの保管場所（D1）を作る          ← 予約・割り当て・出勤可否を入れる箱
        ↓
  ③ 箱の中に表を作る（SQLを貼って実行）    ← 13個のテーブルができる
        ↓
  ④ GitHubのコードとCloudflareをつなぐ     ← 以降、コードを更新すると自動で反映される
        ↓
  ⑤ 秘密の鍵を2つ登録する
        ↓
  ⑥ 動いているか確認する
```

**用語**（初回だけ気になるので）

| 言葉 | 意味 |
|---|---|
| Cloudflare | 今回システムを動かす場所。無料枠で足ります |
| Workers | プログラムを動かす仕組み。今回のシステム本体 |
| D1 | Cloudflare のデータベース。予約や割り当てを保存する場所 |
| cron（クーロン） | 決まった時刻に自動実行する仕組み。毎朝6時の処理に使います |
| デプロイ | 書いたコードを実際に動く状態にすること |

---

## ① Cloudflare のアカウントを作る

1. https://dash.cloudflare.com/sign-up をブラウザで開く
2. メールアドレスとパスワードを入れて登録
   - **クレジットカードの登録は不要**です。求められたらプラン選択を間違えている可能性があります
3. 確認メールが届くのでリンクをクリックして有効化
4. ログインすると「Cloudflare ダッシュボード」が開きます。ここが今後の作業場所です

> **名義について**: 今回はあなたのアカウントで作ります。将来経営者に引き継ぐ可能性があるなら、
> あとで **Manage Account → Members → Invite** から経営者を Administrator として招待しておくと、
> 名義変更よりずっと簡単に移せます。今やらなくても大丈夫です。

---

## ② データの保管場所（D1）を作る

1. 左メニューの **Storage & Databases** をクリック → **D1 SQL Database** を選ぶ
2. **Create** ボタンを押す
3. Database name に **`cleaning-schedule`** と入力
   - ⚠ この名前は正確に入れてください。プログラム側の設定と一致していないと動きません
4. **Create** を押す

作成されると、そのデータベースの画面が開きます。この画面はこの後も使います。

---

## ③ 箱の中に表を作る

いま作ったデータベースは空っぽなので、テーブル（表）を作ります。

1. データベースの画面で **Console** タブを開く
   - SQL を入力して実行できる画面です
2. GitHub で
   [migrations/0001_init.sql](https://github.com/issa311sas-hub/flower_apps/blob/main/apps/cleaning-schedule/migrations/0001_init.sql)
   を開き、右上のコピーボタンで**中身を全部コピー**する
3. Console に貼り付けて **Execute**（実行）を押す
4. 続けて
   [migrations/0002_seed_master.sql](https://github.com/issa311sas-hub/flower_apps/blob/main/apps/cleaning-schedule/migrations/0002_seed_master.sql)
   も同じようにコピーして貼り付け、**Execute**
   - こちらは9ユニット（b2〜c4）と担当者4名（細田さん・普久原さん・福田さん・Rクリーン）、
     既定の設定を入れるものです

### うまくいったかの確認

Console に次を貼って実行してみてください。

```sql
SELECT name, sort_order FROM units ORDER BY sort_order;
```

`b4, b5, b6, b2, b3, s1, s2, s3, c4` の9行が出れば成功です。

```sql
SELECT name, priority, default_capacity FROM staff ORDER BY priority;
```

細田さん(1) → 普久原さん(2) → 福田さん(3) → Rクリーン(99) が出ればOKです。

> **もし長すぎて弾かれたら**: `0001_init.sql` を `CREATE TABLE` ごとに分けて、
> 何回かに分けて実行してください。順番は上から順で問題ありません。

### ④に進む前に: database_id を控える

1. データベース画面の右側（または Settings）に **Database ID** が表示されています
2. `1a2b3c4d-...` のような文字列です。**これをコピーして私に貼ってください**
   - このIDは秘密情報ではありません（これだけでは誰もアクセスできません）
   - ⚠ ただし後で出てくる **API トークンは絶対にチャットに貼らないでください**

私がプログラム側の設定ファイル（`wrangler.jsonc`）にこのIDを書き込んで反映します。
**ここで一度作業が止まります。** IDを貼っていただいたら続きを案内します。

---

## ④ GitHub のコードと Cloudflare をつなぐ

ここまでで箱ができました。次は中で動くプログラムを載せます。
一度つないでおけば、**以降はコードを更新するだけで自動で反映**されます。

1. 左メニューの **Workers & Pages** をクリック
2. **Create application** を押す
3. **Import a repository**（リポジトリを取り込む）の側にある **Get started** を押す
4. GitHub アカウントの接続を求められるので許可する
   - リポジトリを選ぶ画面で `issa311sas-hub/flower_apps` を選択
   - 「すべてのリポジトリ」ではなく、このリポジトリだけを許可すれば十分です
5. 設定画面が出るので、次のとおり入力します

| 項目 | 入れる値 | 補足 |
|---|---|---|
| Project name | `cleaning-schedule` | URL の一部になります |
| Production branch | `main` | |
| **Root directory** | **`apps/cleaning-schedule`** | ⚠ **ここが最重要。** 指定を忘れるとリポジトリの一番上を見に行って必ず失敗します |
| Build command | `npm test` | テストが落ちたらデプロイされない安全装置になります |
| Deploy command | `npx wrangler deploy` | |

6. **Save and Deploy**（または Create and deploy）を押す

初回は3〜5分かかります。ログが流れるので眺めていてください。

### 失敗したときの見方

**Builds** タブに履歴が出ます。失敗したビルドを開くとログが読めます。よくある原因:

| ログに出る内容 | 原因 |
|---|---|
| `package.json` が見つからない | Root directory の指定漏れ（④の5番） |
| `Missing entry-point` / `public` が無い | コードが古い。最新の `main` になっているか確認 |
| `database_id` に関するエラー | ③の最後で控えたIDが設定に入っていない |
| テストの失敗 | プログラム側の問題です。ログを貼ってください |

## ⑤ 秘密の鍵を2つ登録する

ログインの仕組みと、Beds24 のトークンを暗号化して保存するために使います。

### 値を作る（ブラウザだけでできます）

1. デプロイされた自分のサイトを開き、キーボードの **F12** を押して開発者ツールを出す
2. **Console** タブに次を貼って Enter

```javascript
crypto.getRandomValues(new Uint8Array(32)).reduce((s, b) => s + b.toString(16).padStart(2, '0'), '')
```

3. 出てきた64文字の文字列をコピー（これが1つ目）
4. もう一度同じコマンドを実行して、別の値をコピー（これが2つ目）

> この2つはパスワードと同じ扱いです。**チャットにも貼らないでください。**
> メモ帳に一時的に置いて、登録できたら消してください。

### 登録する

1. **Workers & Pages** → `cleaning-schedule` を開く
2. **Settings** タブ → **Variables and Secrets**
3. **Add** を押し、次の2つを登録する（Type は必ず **Secret** を選ぶ）

| Variable name | Value |
|---|---|
| `SESSION_PEPPER` | 1つ目の値 |
| `TOKEN_ENC_KEY` | 2つ目の値 |

4. **Deploy**（保存して再デプロイ）を押す

> **なぜ Beds24 のトークンは Secret に入れないのか**
> Beds24 はトークンを使うたびに新しいものを発行し直す仕組み（ローテーション）です。
> Cloudflare の Secret は動作中のプログラムから書き換えられないため、Beds24 のトークンは
> D1 に暗号化して保存します。`TOKEN_ENC_KEY` はその暗号化に使う鍵です。

## ⑥ 動いているか確認する

次の5つを確認できたら完了です。

### 1. サイトが開く

`https://cleaning-schedule.<あなたのサブドメイン>.workers.dev`

「清掃予定管理（準備中）」というページが出ます。まだ画面は作っていないので、これで正常です。

### 2. データベースにつながっている

上のURLの末尾に `/api/health` を付けて開きます。

```json
{
  "ok": true,
  "d1": {
    "connected": true,
    "units": 9,
    "staff": ["細田さん", "普久原さん", "福田さん", "Rクリーン"]
  }
}
```

`"ok": true` で、`units` が 9、`staff` に4名出ていればD1との接続まで通っています。
`"ok": false` の場合は `error` に理由が書いてあるので、その文面を貼ってください。

### 3. 自動実行が登録されている

**Settings** → **Triggers**（またはCron Triggers）に2件あるか確認します。

| cron | 実際に動く時刻（日本時間） | 役割 |
|---|---|---|
| `0 21 * * *` | 毎日 **翌朝6時** | Beds24取得 → 割り当て → 通知 |
| `0 9 * * *` | 毎日 **18時** | トークンの維持・稼働監視 |

> ⚠ **cron の時刻は UTC（世界標準時）で書きます。** 日本時間より9時間遅れです。
> `0 21` は「21時」ではなく「翌朝6時」。ここは半年後に見て混乱しやすいので覚えておいてください。

### 4. GitHub 側のテストも通っている

GitHub のリポジトリ → **Actions** タブ → 最新の実行が緑のチェックになっていること（テスト92件）。

### 5. コードの更新が自動で反映される

以降、コードを更新して `main` に反映すると、Cloudflare が自動でテスト→デプロイします。
**あなたがターミナルを触ることはもうありません。**

## 費用について

無料枠に収まる想定です。

| 項目 | 無料枠 | このシステムの想定 |
|---|---|---|
| リクエスト数 | 100,000/日 | 200〜500/日 |
| D1 の読み取り / 書き込み | 500万 / 10万（1日） | 数千 / 数百 |
| D1 の保存容量 | 5 GB | 数 MB |
| 自動実行（cron） | 5個 | 2個 |

ひとつだけ注意が要るのが **CPU時間（無料プランは1リクエスト10ms）** です。
ログイン時のパスワード照合がここに引っかかる可能性があるため、
ログイン機能を作った直後に実測します。もし超えるようなら調整するか、
Workers 有料プラン（月$5）に上げる判断になります。**その時点で必ず相談します。**

---

## 困ったときの連絡の仕方

うまくいかないときは、次のどれかを貼ってもらえると原因が特定できます。

- Builds タブの**失敗したビルドのログ**（最後の20行くらい）
- `/api/health` の**表示内容そのまま**
- D1 Console でエラーが出たなら、その**エラーメッセージ**

**API トークン・`SESSION_PEPPER`・`TOKEN_ENC_KEY` の値は貼らないでください。**
それ以外（database_id、URL、エラーメッセージ）は貼って問題ありません。
