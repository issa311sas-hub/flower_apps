# v17 — イベント入力を1画面にまとめる

## 変更した理由

v16 のイベント入力は、10個のイベントを1件ずつダイアログで聞く形だった。
**10回もダイアログが出るのは実用に耐えない。** 1画面で10個入力したい。

## 変更内容

### ユーザーフォームで1画面にした

`.bas` だけではユーザーフォームを配れない（部品の配置がバイナリの `.frx` に
入るため）。そこで、**部品を1つも置かない空のフォームを作ってもらい、
入力欄とボタンはコードが実行時に作る**方式にした。

利用者の作業は1回だけ、2分で終わる。

1. VBE で 挿入 → ユーザーフォーム（空のままでよい）
2. オブジェクト名を `F_イベント入力` に変える
3. `vba/userform/F_イベント入力.txt` の中身を貼り付ける

**コピー＆ペーストで貼るので文字化けしない**（`.bas` の取り込みと違う点）。

### フォームが無くても動く

`M06_Events` が `UserForms.Add` の成否でフォームの有無を判定し、
無ければ従来どおり1件ずつ聞くダイアログに切り替える。
フォームを作っていない環境でも、機能は同じように使える。

`ボタン_導入状態を確認` に、フォームがあるかどうかの表示を足した。

```
■ イベント入力フォーム
  OK  F_イベント入力 : 1画面でまとめて入力できます
```

### フォームとモジュールの役割分担

フォーム側は**レイアウトだけ**を持つ。表示する名前・初期値・結果の受け渡しは
すべて `M06_Events` の `EventForm〇〇` 関数を通す。
イベントを増やしても、貼り付けたフォームのコードは直さなくてよい。

| 関数 | 役割 |
|---|---|
| `EventFormCount` | 入力欄の数 |
| `EventFormLabel(i)` | 各行の見出し（イベント名） |
| `EventFormDefault(i)` | 初期値（いま工程表に書かれている日付） |
| `EventFormTitle` / `EventFormHeader` | タイトルと説明文 |
| `EventFormSetResult(i, s)` | 入力された文字を戻す |
| `EventFormSetOK(b)` | 「書き込む」が押されたか |

### 入力の意味を変えた（フォームのとき）

1画面だと、画面がそのまま結果を表しているのが分かりやすい。

| 入力 | 動き |
|---|---|
| 日付を入れる | その日の列に書き込む |
| **空欄にする** | **そのイベントを消す** |
| 触らない | 変更しない |
| 「やめる」／× | 何も書き込まない |

1件ずつ聞くダイアログのときは、これまでどおり
「空欄＝変更しない」「`-`＝消す」のまま（1画面と違って全体が見えないため）。

## 実機で確認してほしいこと

1. フォームを作って `ボタン_イベントを入力` → 10個の入力欄が1画面で出るか
2. `ボタン_導入状態を確認` に「イベント入力フォーム OK」と出るか

## 既知の問題

- フォームは**手で1回作る必要がある**。ブックを配り直すときも、
  そのブックにフォームが入っていれば作り直しは不要。
- 入力欄は日付の文字列。カレンダーから選ぶ形ではない。
