# v18 — 入力を本当に1画面にする・結合セルへの対応・M0/M1 の位置修正

## 変更した理由

1. **10回ダイアログが出る。** v17 のユーザーフォームは1画面だが、
   フォームを作っていない環境では1件ずつ聞く形に落ちるため、
   結局10回切り替わる。**設定なしで1画面**にしたい。
2. **M0 / M1 が表示されない。** 工程表は 3〜4マス目 と 5〜6マス目 が
   結合されており、結合セルは左上にしか文字が入らないため。
   位置も 6マス目ではなく **4マス目**が正しい。
3. 家具搬入・CL・クリーンハウスの書式変更（結合・太字）。

## 変更内容

### 設定なしで1画面になった（入力シート方式）

ユーザーフォームは `.bas` で配れないため、**「イベント入力」シート**を
その場で作って1画面の入力欄にする方式を足した。

- 10行の入力欄（イベント名・日付・書き込む場所の説明）が並ぶ
- 「書き込む」「やめる」のボタンをシート上に置く
- 入力が終わるとシートは削除され、工程表に戻る
- 対象の物件は、シートの H 列（非表示）に覚えさせる
  （ボタンから続きを実行するため、マクロが一度終わっても分かるようにする）

ユーザーフォーム `F_イベント入力` がブックにあれば、これまでどおり
フォームを使う。**どちらも1画面。1件ずつ聞く方式は廃止した。**

### 結合されたセルに対応した

工程表は 3〜4マス目・5〜6マス目 が結合されていることがある。
結合セルは左上にしか文字が入らず、それ以外に書いても表示されない。

`EventCell` を追加し、書き込み・読み取り・削除のすべてで
**`MergeArea` の左上に読み替える**ようにした。

複数マスを使うイベントは、必要なら**その範囲を結合してから**書く。
消すときは、自分で結合したものだけ結合を戻す
（結合の行数・列数が定義と一致するときだけ）。

### 書き込む位置と書式（変更後）

| イベント | 位置 | 文字色 | 向き | その他 |
|---|---|---|---|---|
| M0 / M1 | **上から4マス目** | 黒 | 横書き | v17 は6マス目（表示されなかった） |
| M2 / M3 / M4 / M5 | 上から2マス目 | 黒 | 横書き | |
| 家具搬入 | **上から2〜3マス目（結合）** | 赤 | 縦書き | **太字** |
| CL | **上から2〜3マス目（結合）** | 赤 | 縦書き | |
| クリーンハウス | **上から1〜3マス目（結合）** | 黒 | 縦書き | |
| 2W | 上から2マス目 | 赤 | 横書き | 塗りつぶしを消す |

イベント定義は7項目になった
（名前 / 行オフセット / 行数 / 文字色 / 太字 / 縦書き / 塗りを消す）。

## 実機で確認してほしいこと

1. `ボタン_イベントを入力` で「イベント入力」シートが1画面で開くか
2. M0 / M1 が表示されるか（結合セルの左上に入るか）
3. 家具搬入・CL・クリーンハウスが結合されたマスに縦書きで入るか

## 判断が要った点

- 「上から◯マス目」は、**結合を数えない生のマス**として解釈した
  （M0/M1 の「4マス目」= ブロック先頭 +3、その結合の左上は +2 になる）。
- クリーンハウスの「1〜3マス目を結合」は、**躯体の色帯の行（1マス目）を含む**。
  その列は躯体の色が塗れなくなるので、躯体工事と重なる日に入れると
  色が消えたように見える可能性がある。

## 既知の問題

- 入力シートはマクロが作って消す。ブックを保存する前に Excel が落ちると
  シートが残ることがあるが、次に開くときに作り直すので実害はない。
- 結合は工程表の見た目を変える操作なので、**元に戻す（Ctrl+Z）は効かない**。
