# v10 - 2026-08-11 空欄のところだけ埋める

## 変更理由
v8 で「終了日は出力専用、毎回上書き」としたが、これは要望の読み違いだった。
**会社やお客様の都合で日程を人が決めて手入力する**場面があり、
そこを計算で書き換えられては困る、というのが本来の趣旨だった。

## 変更内容

### 入っている値には触らない
計算して書き込むのは**空欄のセルだけ**にした。

| 列 | 空欄のとき | 入力してあるとき |
|---|---|---|
| 基礎開始日 | 計画対象外 | その日を使う |
| 躯体開始日 | 基礎終了日 + 間隔から決めて書き込む | その日を使う |
| 終了日 | 工期の式で計算して書き込む | **その日を使う（計算しない）** |
| 色名 | 空いている業者を割り当てて書き込む | その業者で固定 |

手入力の日程も業者の占有として数えるので、自動割り当てが人の予定と被らない。

### 設計が単純になった
v8 で入れた「前回の自動値かどうか」の判定（`SnapshotEndDates` /
`WasAutoStart`）が不要になり、削除した。
空欄かどうかだけで判断できるので、挙動が読みやすい。

### ボタン_選択行の計算結果をクリア（新規）
日程を引き直したい行だけを選んでクリアできるようにした。

雨でずれたときの手順:
1. `M_工程データ` で対象の行を選択
2. `ボタン_選択行の計算結果をクリア`
3. 基礎開始日を直す
4. `ボタン_工程を作る`

## トレードオフ
**クリアせずに開始日だけ直すと、終了日は前のまま残る。**
v8 で直した「雨ズレで自動追随」は、明示的なクリア操作に置き換わった。
人の手入力を守ることを優先した結果で、手順書に明記した。

## 検証
```
1) 基礎開始日だけ入力   基礎 09/01～09/12(計算)  躯体 09/16～09/19(自動)
2) そのまま再実行       何も変わらない
3) 基礎終了日を 09/25 に手入力
                        基礎 09/01～09/25(手入力を尊重)
                        躯体 09/29～10/02(そこから引き直し)
4) 躯体開始日を 10/12 に固定
                        躯体 10/12～10/16(開始日を尊重、終了日だけ計算)
5) クリアして 09/04 へ  基礎 09/04～09/16  躯体 09/22～09/25
```
