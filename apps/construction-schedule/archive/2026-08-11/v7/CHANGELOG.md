# v7 - 2026-08-11 躯体工事の追加と M_工程データ の横並び化

## 変更理由
- 基礎工事に加えて躯体工事も工程表に書けるようにしたい。
- `M_工程データ` が「1行1工程」の縦持ちだと、同じ物件の基礎と躯体が
  離れた行に散らばる。**横に並んでいれば同じ担当かどうかを目で追える**ため、
  実務上そちらが楽だという要望を受けた。

## 変更内容

### M_工程データ を1物件1行の横並びに
```
A 契約番号 | B 邸名 | C-F 基礎 | G-J 躯体 | （以降 工程を足すごとに右へ4列ずつ）
```
各工程ブロックは 開始日 / 終了日 / 色名 / 備考 の4列。
旧形式（縦持ち）が残っていたら `M_工程データ_旧1` に退避して作り直す。

### 躯体工事の自動生成
- 躯体開始日が空欄なら、**基礎の終了日 + 4日（暦日）** から自動で決めて書き込む。
  間隔は `M_工期` の「基礎完了→躯体着手」から読む。
- 躯体の業者は `M_業者` の工種「躯体」（初期は茶・薄紫の2チーム）から割り当てる。

### 色帯を塗る行を実測に合わせて修正
過去データを数えたところ、工程によって塗る行数が違っていた。

| 工程 | 塗る行 | 実測セル数 |
|---|---|---|
| 基礎 | +4 と +5 の2行 | 2610 / 2621 |
| 躯体 | **+0 の1行のみ** | +0:808 に対し +1 は19 |

v6 までは躯体を +0/+1 の2行に塗っていたので、これを1行に直した。

### 手入力の優先ルールを整理
| 列 | 空欄のとき | 入力してあるとき |
|---|---|---|
| 基礎開始日 | 計画対象外 | その日から計算 |
| 躯体開始日 | 基礎終了日から自動決定 | その日から計算 |
| 終了日 | 工期の式で計算 | その日付が優先される |
| 色名 | 空いている業者を自動割り当て | その業者で固定 |

### モジュール構成の整理
- `M05_KisoPlan.bas` → **`M05_Plan.bas`** に改名。工程を1つずつ足せる構造にした。
  工程を追加するときは `TASK_COUNT` と `TaskName` / `TaskRowOffsets` /
  `TaskInterval` に Case を足すだけでよい。
- `M04_Repaint.bas` を**削除**。色塗りは `M05_Plan` に一本化し、
  重複チェックも同モジュールへ移した。「色を塗り直す」は「工程を作る」に統合。
- モジュールは **7つ → 6つ**。

### ボタンの変更
| 旧 | 新 |
|---|---|
| `ボタン_基礎の工程を作る` | `ボタン_工程を作る` |
| `ボタン_基礎の業者割当をクリア` | `ボタン_工程の計算結果をクリア` |
| `ボタン_色を塗り直す` | 廃止（`ボタン_工程を作る` に統合） |

## 取り込み時の注意
**モジュール名が変わり、1つ減っています。**
必ず既存の標準モジュールを**すべて解放してから**6つ入れ直してください。
`M04_Repaint` や `M05_KisoPlan` が残っていると、関数名の重複でコンパイルエラーになります。

## 既知の制約
- 色帯は開始日から連続で塗る。実物の基礎は養生で途切れるが未対応（確認事項 Q4）。
- 躯体の業者は初期状態で2チームのみ。同時期に3件重なると未割当が出る。
