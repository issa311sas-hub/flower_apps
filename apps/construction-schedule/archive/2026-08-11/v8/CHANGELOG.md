# v8 - 2026-08-11 開始日を直せば全部計算し直す

## 変更理由
「雨で工期がズレた場合、開始日を変更するだけで全て再計算されるか」という
問いを受けてコードを追ったところ、**v7 では再計算されないことが分かった。**

### バグ1: 終了日が古いまま使われる
```vb
If IsDate(終了日) And 終了日 >= dStart Then
    dEnd = 終了日          ' ← 前回の実行で書き込まれた値
```
初回実行で終了日が埋まるため、2回目以降は「手入力」とみなされて温存された。
開始日を後ろへずらしても古い終了日が使われ、**工期が黙って縮んでいた。**
ずらし幅が大きく `終了日 < 新開始日` になったときだけ再計算されるという、
一貫しない挙動だった。

### バグ2: 躯体が基礎に追随しない
躯体開始日は初回実行時にシートへ書き戻していた。2回目以降はそれが
「手入力」と区別できず、基礎がずれても躯体は動かなかった。

どちらも「入力欄と出力欄が同じセル」であることが原因。

## 変更内容

### 終了日を出力専用にした
毎回かならず `開始日 + 工期` で計算し直して上書きする。
セルは薄いグレーで塗り、入力欄と見分けられるようにした。

### 調整列を追加（工程あたり4列 → 5列）
```
開始日 | 調整 | 終了日 | 色名 | 備考
```
終了日を手で直せなくなった代わりに、**調整列**で日数を足し引きする。
`+1` で1日長く、`-2` で2日短くなる。
議事録の「算出後に人力で +1日 +2日 等の微調整を加えられる仕組み」に対応する。

### 躯体開始日の自動判定
実行前に終了日を控えておき（`SnapshotEndDates`）、躯体開始日が
「前回の基礎終了日 + インターバル」と一致するかを見る（`WasAutoStart`）。
一致すれば前回自動で入れた値とみなし、新しい基礎終了日から入れ直す。
手で書いた日付とは一致しないので、手入力は温存される。

### ClearPlanResults の対象を拡張
終了日・色名に加えて、2番目以降の開始日も消すようにした。
残すと、前工程がずれたときに追随できなくなるため。

## 検証
雨ズレのシナリオを同じロジックで再現して確認した。

```
1回目            基礎 09/01～09/12    躯体 09/16～09/19
  ↓ C列を 09/04 に直して再実行
2回目            基礎 09/04～09/16    躯体 09/21～09/24
                 基礎の稼働日数 11日 → 11日（縮まない）
  ↓ 躯体開始日を手で 10/05 に固定して再実行
3回目            基礎 09/04～09/16    躯体 10/05～10/08（手入力は温存）
  ↓ さらに基礎を 09/09 へ
4回目            基礎 09/09～09/21    躯体 10/05～10/08（固定は動かない）
```
