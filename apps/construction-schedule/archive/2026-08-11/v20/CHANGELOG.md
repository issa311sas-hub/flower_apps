# v20 — 1ファイルで導入・更新できるようにする

## 変更した理由

更新のたびに **7つの `.bas` をダウンロードして、1つずつ取り込む**のが手間だった。
1ファイルで済むようにしたい。

## 変更内容

### ローダー方式（M90_Loader を新設）

全モジュールを1つのテキストファイルにまとめ、それを読んで
**VBA プロジェクトへ一括で流し込む**ローダーを追加した。

```
dist/工程表マクロ.txt   ← 利用者がダウンロードするのはこれだけ
```

利用者の手順

| | 作業 |
|---|---|
| 最初の1回だけ | トラスト センターで「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」にチェック |
| 最初の1回だけ | `vba/sjis/M90_Loader.bas` を取り込む |
| 毎回の更新 | `ボタン_マクロを更新` → ファイルを選ぶ → 「はい」 |

### 文字化けが起きなくなった

ローダーは `ADODB.Stream` で **UTF-8 として読み**、`CodeModule.AddFromString`
で流し込む。VBE の「ファイルのインポート」（ANSI 決め打ち）を通らないため、
Shift-JIS への変換が不要になり、文字化けの経路そのものが無くなる。

`vba/sjis/` は手で取り込む場合のために残してある。

### ユーザーフォームも一緒に入る

`VBComponents.Add(3)` でユーザーフォームを作り、コードを流し込む。
イベント入力のポップアップ `F_イベント入力` を**手で作る必要がなくなった**
（v17〜v19 では手で貼り付ける必要があった）。

部品は実行時にコードが作るため、フォームのバイナリ（`.frx`）は要らない。

### 中身の切り分け

まとめたファイルは、行頭の目印でモジュールを区切る。

```
'>>>MODULE:M00_Config
'>>>USERFORM:F_イベント入力
```

判定は「行頭がアポストロフィ＋目印」のときだけ。
説明文のなかに目印の文字列が出てきても切らない。

### 自分自身は入れ替えない

実行中のモジュールを消すと止まるため、`M90_Loader` だけは飛ばす。
ローダーを新しくするときだけ、手でインポートし直す。

### ツール

```bash
python tools/make_import_bas.py   # vba/sjis/ を作る（手で取り込む用）
python tools/make_bundle.py       # dist/工程表マクロ.txt を作る（1ファイル用）
```

## 実機で確認してほしいこと

1. トラスト センターの設定 → `M90_Loader.bas` を取り込む → `ボタン_マクロを更新`
2. 入れ替えたあと**ブックを保存**（保存しないと元に戻る）
3. `ボタン_モジュール一覧` で、8モジュール + フォームが入っているか

## 既知の問題

- トラスト センターの設定が要る。会社の方針で変えられない場合は、
  これまでどおり `vba/sjis/` を手で取り込む方法も使える（機能は同じ）。
- 入れ替えは元に戻せない。実行前にブックをコピーしておくと安全。
- ローダー自身は更新されない。
