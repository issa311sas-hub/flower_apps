# v3 - 2026-07-20 差分同期・API最適化・新入力フォーマット

## 変更理由
- Google Calendar APIの読み書き量が多く、レート制限に引っかかる問題
- 予約の入れ替わり検知のため、予約IDベースのデータ管理が必要
- 経営者が手動でカレンダーを編集するケースへの対応
- 顧客の特殊要望（タイトル）をカレンダー出力に含めたい

## 変更内容

### 入力データ形式の変更
- **旧**: チェックアウト日, ユニット, ゲスト, 泊数（4列）
- **新**: 予約ID, タイトル, チェックアウト日, ユニット（4列）
- 予約IDで個別の予約を一意に識別可能に
- タイトルに顧客の特殊要望（消毒ポット、ベビーベッド等）を保持

### 同期データベースシート（新規追加）
- シート名: `同期データベース`
- 列: 予約ID / チェックアウト日 / ユニット / タイトル / 担当 / イベントID / 最終同期
- 前回のカレンダー同期状態を保管し、差分検出の基盤とする
- カレンダーイベントIDを記録し、個別のイベント操作を可能に

### カレンダー書き込みの最適化
- **旧**: 毎回、対象範囲の全イベントを削除→全件再作成
- **新**: DBと比較し、新規・変更分のみ作成、削除分のみ削除
- 変更のないイベントには一切触れない（手動編集が保持される）
- API呼び出し回数の大幅削減（例: 150件中10件変更 → 10回 vs 旧60回）

### カレンダー読み込みの最適化
- **旧**: 全スタッフ×全日付範囲のカレンダーを毎回読み込み
- **新**: 新規予約がある日付のみ、必要なスタッフのカレンダーを読み込み
- 変更のない日はカレンダー読み込みをスキップ

### カレンダー出力フォーマット
- **旧**: `担当⇒unit1.unit2`（日付+担当でグループ化）
- **新**: `担当⇒unit` または `担当⇒unit(タイトル)`（予約単位で個別イベント）
- タイトルがある場合のみ括弧付きで表示（例: `細田さん⇒b1(消毒ポット)`）
- イベント説明に予約IDを記載

### マッチングアルゴリズムの改善
- 既存の割り当て（DB内の未変更予約）はそのまま保持
- 新規・変更分のみ割り当てを計算（既存のスタッフ負荷を考慮）
- 優先割り当て・均等化ロジックは既存負荷を差し引いた残り容量で計算

### 割り当て結果シートの拡張
- **旧**: 日付, 曜日, ユニット, 担当, ステータス（5列）
- **新**: 予約ID, 日付, 曜日, ユニット, タイトル, 担当, ステータス（7列）
