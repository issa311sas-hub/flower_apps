## 2026-07-20 仕様変更: 割り当てロジック＋カレンダー入力方式

### 変更の背景
- 調査の結果、普久原さんは全曜日対応可能と判明（細田さんは変わらず月火木日）
- 1日の処理上限もスタッフが都度カレンダーで申告する方式に変更
- 経営者から優先割り当て＋均等化の要望あり

### 変更内容

#### 1. カレンダー入力方式の変更
- **旧**: ×(不可) を入力。入力なし＝出勤可
- **新**: 数字0〜9を入力（その日の対応可能件数）。入力なし＝デフォルト上限（スタッフは0=不可、Rクリーンは99=常時可）
- フェイルセーフ: 入力忘れ→出勤不可扱いとなり、誤って割り当てられることを防ぐ
- 対応フォーマット: 半角(0-9)・全角(０-９)・丸付き数字(⓪-⑨)

#### 2. 曜日固定テーブルの廃止
- **旧**: 設定シートに「曜日別処理上限」テーブル（月=細田3件、水=普久原3件...）
- **新**: 固定テーブル廃止。処理可能件数はカレンダーの数字入力で都度決定

#### 3. 優先割り当て＋均等化ロジック
- **優先ルール**: 月火木日は細田さんに2件まで優先的に割り当て
- **均等化ルール**: 4件以上 かつ 両者出勤 → 処理件数を均等に分配（例: 4件→2-2、5件→3-2）
- **非優先曜日(水金土)**: 普久原さんを先に割り当て
- **Rクリーン**: どちらも対応不可な分を割り当て（従来通り）

### 設計上の確定事項まとめ（v2時点）

- **入力**: Beds24 Excelを週1回手動でスプレッドシートに貼り付け（変更なし）
- **スタッフ予定**: Googleカレンダーに **数字(0〜9)** で対応可能件数を入力
- **マッチング**: 優先割り当て(2件) → 均等化(4件以上) → Rクリーン(残り)
- **外注**: スタッフで対応不可 → Rクリーンに自動割り当て（変更なし）
- **UI**: PC向けスプレッドシート（変更なし）
- **スタッフ出勤日**: 細田さん=月火木日 / 普久原さん=全曜日 / Rクリーン=常時

## 2026-07-20 仕様変更: 差分同期・API最適化・新入力フォーマット

### 変更の背景
- Google Calendar APIの読み書き量が多く、レート制限に引っかかる
- 予約の入れ替わりを検知できない（予約IDがなかった）
- 経営者が手動でカレンダーの割り振りを変更するケースがある
- 顧客の特殊要望（消毒ポット、ベビーベッド等）をカレンダーに表示したい

### 変更内容

#### 1. 入力データ形式の変更
- **旧**: チェックアウト日, ユニット, ゲスト, 泊数
- **新**: 予約ID, タイトル, チェックアウト日, ユニット
- 予約IDで個別の予約を一意に識別し、差分検出の基盤とする
- タイトルで顧客の特殊要望を保持

#### 2. 同期データベースシート（新規追加）
- スプレッドシート内に「同期データベース」シートを追加
- 前回同期時の状態（予約ID・担当・カレンダーイベントID等）を保管
- 次回実行時にDBと新データを比較して差分のみ処理

#### 3. カレンダーAPI呼び出しの最適化
- **書き込み**: 毎回全削除→全作成 → 差分のみ作成・削除（大幅削減）
- **読み込み**: 全日付範囲 → 新規予約がある日付のみ
- 変更のないイベントには一切触れない

#### 4. 手動カレンダー編集の保持
- 経営者が手動でカレンダーを書き換えた場合、次回実行で上書きしない
- DBの差分のみ更新するため、手動変更は自然に保持される

#### 5. カレンダー出力にタイトルを含む
- タイトルがある予約: `担当⇒unit(タイトル)` 例: `細田さん⇒b1(消毒ポット)`
- タイトルなしの予約: `担当⇒unit` 例: `普久原さん⇒c4`

### 設計上の確定事項まとめ（v3時点）

- **入力**: Beds24 Excelを週1回手動でスプレッドシートに貼り付け（形式変更: 予約ID付き4列）
- **スタッフ予定**: Googleカレンダーに数字(0〜9)で対応可能件数を入力（変更なし）
- **マッチング**: 既存割り当て保持 + 新規分のみ割り当て（変更なし → Rクリーン → 未割当）
- **カレンダー同期**: 差分のみ書き込み（API呼び出し最小化）
- **手動編集**: 経営者のカレンダー手動変更は保持
- **UI**: PC向けスプレッドシート（変更なし）+ 同期データベースシート追加

## 2026-07-20 仕様変更: 翌日清掃ルール追加

### 変更の背景
- タイトルに「翌日清掃」を含む予約がRクリーン（外注）に回ると不要なコストが発生する
- 翌日にスタッフが対応可能であれば、翌日に清掃を回す方が経済合理性が高い
- 翌日に宿泊予定がないユニットであれば、翌日清掃でも運営上支障がない

### 変更内容

#### 1. 翌日清掃ルール（新規追加）
- **対象**: タイトルに「翌日清掃」を含む予約
- **ロジック**: 2フェーズ方式
  - フェーズ1: 通常の割り当てアルゴリズム（優先→均等化→Rクリーン→未割当）を実行
  - フェーズ2: Rクリーンまたは未割当になった「翌日清掃」対象を、翌日のスタッフに振り替え
- **原則**: 当日スタッフに余裕があれば当日に割り当て。翌日送りは外注回避のための最後の手段
- **ステータス**: 翌日に回った予約は `確定（翌日）` として表示

#### 2. チェックアウト日と清掃日の分離
- **旧(v3)**: チェックアウト日＝清掃日（常に同日）
- **新(v4)**: チェックアウト日と清掃日を別管理。翌日清掃の場合、清掃日＝チェックアウト日+1
- DBに「清掃日」列を追加（8列構成）。v3の7列DBも後方互換で読み込み可能

#### 3. カレンダー表示の変更
- カレンダーイベントの日付は「清掃日」を使用
- 翌日清掃の予約はチェックアウト翌日のカレンダーに表示される

### 設計上の確定事項まとめ（v4時点）

- **入力**: Beds24 Excelを週1回手動でスプレッドシートに貼り付け（変更なし）
- **スタッフ予定**: Googleカレンダーに数字(0〜9)で対応可能件数を入力（変更なし）
- **マッチング**: フェーズ1(通常割り当て) → フェーズ2(翌日清掃の振り替え)
- **翌日清掃**: 「翌日清掃」タイトル付き予約は外注回避のため翌日スタッフに優先的に振り替え
- **カレンダー同期**: 差分のみ書き込み（変更なし）。清掃日ベースでイベント日付を決定
- **手動編集**: 経営者のカレンダー手動変更は保持（変更なし）
- **UI**: 割り当て結果に「清掃日」列追加、翌日送り件数を完了メッセージに表示

## 2026-07-22 仕様変更: 入力形式変更・翌日清掃ロジック刷新・害虫防止ルール

### 変更の背景
- タイトルに「翌日清掃」と記載する方式では、直前に予約が入った場合に翌日清掃が間に合わない
- 実際の予約データ（開始日・チェックアウト日）から清掃可能期間を自動判定する方が安全で正確
- ゴミを放置すると害虫が発生するため、清掃はチェックアウトから2日以内に完了する必要がある

### 変更内容

#### 1. 入力データ形式の変更（4列→6列）
- **旧(v4)**: 予約ID, タイトル, チェックアウト日, ユニット
- **新(v5)**: 予約ID, タイトル, 開始日, チェックアウト日, ユニット, ゲスト
- 開始日を追加することで、同一ユニットの予約間ギャップを計算可能に
- ゲスト数を追加することで、Rクリーンのコスト最適化が可能に

#### 2. 翌日清掃判定の刷新
- **旧(v4)**: タイトルに「翌日清掃」を含むかで判定
- **新(v5)**: 同じユニットの次の予約の開始日を見て清掃期限を自動計算
  - 清掃期限 = min(次の予約の開始日 - 1日, チェックアウト日 + 2日)

#### 3. 害虫防止: チェックアウト+2日以内の清掃を保証
- **制約**: 清掃はチェックアウト日、翌日、翌々日のいずれかで完了しなければならない
- **優先順位**: スタッフで+2日以内に清掃 > Rクリーンで+2日以内に清掃 > 清掃未完了（禁止）
- 清掃は早いほうが良い（当日 > 翌日 > 翌々日）

#### 4. 4フェーズ割り当てアルゴリズム
- **Phase 1**: チェックアウト日当日にスタッフ割り当て（細田さん→普久原さん→未割当）
- **Phase 2**: 未割当について +1日・+2日でスタッフ枠を探索（早い日優先）
- **Phase 3**: 14日以内の未割当 → Rクリーン（安全ネット）
- **Phase 4**: Rクリーンコスト最適化（同日のスタッフ担当の中でゲスト数最少の部屋にRクリーンを入れ替え）

### 設計上の確定事項まとめ（v5時点）

- **入力**: Beds24 Excelを週1回手動でスプレッドシートに貼り付け（形式変更: 6列、開始日・ゲスト数追加）
- **スタッフ予定**: Googleカレンダーに数字(0〜9)で対応可能件数を入力（変更なし）
- **マッチング**: Phase 1(当日割り当て) → Phase 2(+1/+2日でスタッフ振り替え) → Phase 3(Rクリーン安全ネット) → Phase 4(Rクリーンコスト最適化)
- **清掃期限**: チェックアウト+2日が絶対上限（害虫防止）
- **カレンダー同期**: 差分のみ書き込み（変更なし）。清掃日ベースでイベント日付を決定
- **キャンセル検知**: DBにあるが予約データから消えた未来の予約 → カレンダーに「キャンセルされました」と表示
- **手動編集**: 経営者のカレンダー手動変更は保持（変更なし）

- **スタッフ予定**: Googleカレンダーに数字(0〜9)で対応可能件数を入力（変更なし）
- **マッチング**: Phase 1〜4（変更なし）
- **清掃期限**: チェックアウト+2日が絶対上限（変更なし）
- **カレンダー同期**: 差分のみ書き込み（変更なし）
- **キャンセル検知**: 変更なし
- **手動編集**: 変更なし
- **タイムライン**: ユニット×日付のガントチャートで清掃延期状況を視覚的に確認可能（新規）
